## 2026-08-08 (4)

Problem: wanted a third RL algorithm beyond GRPO and PPO, specifically one with strong theoretical backing rather than picked for convenience.

Progress: chose TRPO. It has an actual proven monotonic-improvement guarantee (Schulman et al. 2015, building on Kakade and Langford 2002's conservative policy iteration bound), which is the real result PPO's clipped surrogate only heuristically approximates; Agarwal, Kakade, Lee, and Mahajan's JMLR 2021 paper is the reference for how far policy-gradient convergence theory (NPG in particular, TRPO's ancestor) actually goes. Flagged honestly: TRPO's usual dealbreaker is that its per-step cost (conjugate-gradient Fisher-vector products) scales with trainable parameter count, which is why it lost to PPO for full LLM fine-tuning -- but this project only trains LoRA adapters, several orders of magnitude fewer parameters, so the cost calculation might come out differently here. This is my own extrapolation, not backed by an existing TRPO+LoRA paper (didn't find one), so it's a hypothesis for the Stage 2 pilot to test, not an assumption. No MLX implementation of TRPO exists; it has to be built from scratch on top of mlx-lm-lora's existing rollout code.

Updated PLAN.md: Stage 2 now runs GRPO, PPO, and TRPO from the same SFT-diverse checkpoint (isolating algorithm as the only variable), while the SFT-narrow checkpoint gets GRPO only, to keep total RL runs bounded under the M2 budget rather than a full 3x2 cross. Deliverable is now two tables: the original training-method x schema-diversity comparison, plus a new GRPO-vs-PPO-vs-TRPO comparison at fixed diversity that reports cost alongside accuracy. Fallback if TRPO proves too costly to implement correctly: PPO with an adaptive KL penalty instead of clipping, which is easier to build and closer in spirit to TRPO, though it carries none of TRPO's formal guarantee.

Next: unchanged -- pilot RL (GRPO first, since it needs the least new infrastructure) on Qwen2.5-Coder-7B-Instruct-4bit via mlx-lm-lora, build the SQL-execution EX verifier, run the baseline zero-shot eval. TRPO implementation work can wait until GRPO and PPO pilots confirm the rest of the pipeline works.
